# 문서 안내

이 디렉터리는 `me.drugmgr`의 제품 목적, 요구사항, 도메인 규칙, 구현 제약과 개발 현황을 분리해 기록한다. 앱의 최우선 목적은 **실제로 복용한 약·수량·시각과 하루 상태를 빠르고 정확하게 남기고, 권한을 받은 가족과 안전하게 공유하는 것**이다.

## 충돌을 다루는 규칙

1. 같은 주제에 대한 사용자 요청이 중복되거나 서로 다르면 **가장 마지막 요청을 정본**으로 본다. 단, 마지막 요청이 앞선 요청에 내용을 추가한다고 명시한 경우에는 둘을 함께 적용한다.
2. `01`과 `02`의 의료 안전 원칙과 명시적 제외는 다른 문서가 완화할 수 없다. 이를 바꾸는 마지막 사용자 요청이 있더라도 의료 판단이나 안전 경계와 충돌하면 구현 전에 별도 결정이 필요하다.
3. 각 주제는 위 표의 정본 문서가 결정한다. 다른 문서의 요약이 다르면 정본을 따른다.
4. `P0/P1`은 범위와 우선순위다. 구현 완료 여부는 `09-development.md`의 체크박스만 사용한다.
5. 요구사항과 현재 코드·DB가 다르면 요구사항을 완료로 바꾸지 않는다. `09-development.md`에 미충족 항목으로 남기고 구현 또는 제품 결정을 진행한다.
6. 권한, 데이터 필드, 알림처럼 여러 계층에 영향을 주는 결정을 바꿀 때는 관련 정본 문서와 수용 기준을 같은 변경에서 함께 갱신한다.

## 목적 대비 일관성 검토

현재 문서에서 목적을 막는 직접적인 요구사항 충돌은 해소했다. 다음 관계는 서로 반대처럼 보이지만 아래 경계 안에서 함께 유지한다.

| 관계 | 적용하는 경계 |
|---|---|
| 빠른 기록과 저장 정확성 | 입력 동선은 짧게 하되 DB 성공 전 완료로 표시하지 않고, 같은 제출은 `client_request_id`로 멱등 처리한다. |
| 가족 공동 관리와 개인정보 격리 | 기록 소유자가 자신의 공간을 직접 선택해 동의한 관리 요청만 권한으로 만들고 역할별 쓰기 범위를 RLS로 다시 강제한다. 요청 수신자의 기록을 임의로 추론하거나 반대 방향 권한을 자동 생성하지 않는다. |
| 보호자의 약·일정 관리와 소유자 권한 | 보호자는 약·일정·기록을 관리할 수 있지만 공간 이름·구성원·초대는 관리하지 못한다. |
| 설정 변경과 과거 기록 보존 | 약·일정 설정은 앞으로의 동작에 적용하고, 과거 로그의 약·단위·예정 시각 스냅샷은 자동 변경하지 않는다. |
| PWA·Push와 온라인 전용 정책 | 설치와 Push용 서비스 워커만 사용하며 앱 화면·건강 데이터·실패한 쓰기를 오프라인 저장하지 않는다. |
| 반복 알림과 의료 판단 금지 | 알림은 사용자가 만든 일정의 기록 확인만 안내한다. 기록 부재를 미복용으로 판정하거나 복용을 지시하지 않는다. |
| 상태 기록과 의료 해석 금지 | 사용자가 고른 사실과 메모만 보존하고 점수·위험도·투약 권고를 만들지 않는다. |

반복 알림은 알림 피로를, 보호자의 약·일정 삭제는 다른 구성원의 기록 동선과 알림 중단을 유발할 수 있다. 두 기능은 현재 확정 범위이지만 명시적 확인, 행위자 감사 필드, 비의료 문구와 권한 테스트를 계속 유지해야 한다.
