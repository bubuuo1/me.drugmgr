# 기능 요구사항

## 1. 범위 표기

- **P0**: 데이터 정확성과 온라인 운영을 위해 먼저 완료해야 하는 기반
- **P1**: P0 이후 가족이 매일 사용하는 화면과 관리 기능
- **제외**: P0/P1에서 구현하지 않으며 문서의 향후 기능으로도 약속하지 않는 항목

## 2. 공통 요구사항

### 2.1 접근과 데이터

- 사용자는 Vercel URL에 직접 접속한다.
- 로그인, 접근 코드, 기기 승인 화면은 없다.
- 모든 기기는 같은 Supabase 데이터셋을 읽고 쓴다.
- Supabase가 없거나 연결되지 않으면 앱은 설정 오류를 명확히 표시한다.
- 네트워크 또는 Supabase 요청 실패 시 성공으로 표시하지 않는다.
- 앱 데이터는 브라우저 영구 저장소에 저장하지 않는다.
- 온라인으로 다시 연결되더라도 오프라인 중의 동작을 자동 재생하지 않는다.
- Web Push를 켠 기기에는 브라우저가 관리하는 알림 권한과 구독이 남는다. 이 구독은 앱 데이터 캐시나 승인 기기 목록이 아니다.

### 2.2 시간과 날짜

- DB의 순간 시각은 `timestamptz`로 저장한다.
- 화면 표시와 일별 조회 경계는 `Asia/Seoul`을 사용한다.
- 예정 시간과 실제 복용 시각을 분리한다.
- 사용자가 P1에서 실제 시각을 수정해도 최초 생성 시각과 수정 시각은 유지한다.

### 2.3 저장 신뢰성

- 모든 생성·수정·삭제 요청은 완료까지 `await`한다.
- 저장 중에는 같은 제출 동작을 다시 실행할 수 없다.
- 같은 요청의 재시도는 한 건만 생성해야 한다.
- 성공 메시지는 DB 성공 응답 후 표시한다.
- 오류 메시지는 실패한 작업과 재시도 방법을 텍스트로 설명한다.

## 3. P0 요구사항

### 3.1 약과 일정 조회

- Supabase에서 활성 약과 활성 일정을 조회한다.
- 약에는 이름과 단위가 있다.
- 일정에는 약, 예정 현지 시각, 기본 수량, 활성 상태가 있다.
- 홈과 투약 화면은 하드코딩된 약 목록이 아니라 조회 결과를 사용한다.

### 3.2 투약 기록 생성

필수 기록:

- 약
- 복용 수량
- 실제 복용 시각
- 중복 방지용 요청 ID
- 당시 약 이름과 단위

일정에서 시작한 경우 당시 예정 일정 정보도 기록한다. 일정에 연결되지 않은 기록은 `schedule_id`가 없을 수 있다.

수량 버튼은 약의 `quantity_options`를 사용하고 직접 입력을 함께 제공한다. 선택지가 빈 약은 수량 대신 한 번의 복용 여부를 기록한다. 직접 입력은 0보다 큰 허용 값만 저장한다.

### 3.3 오늘 상태 생성

기본 항목:

- 피로
- 근력
- 호흡
- 눈 증상
- 메모

한국 날짜 기준 하루 한 건이며 같은 날짜에 다시 저장하면 별도 중복 행을 만들지 않는다.

### 3.4 기록 확인

- 날짜별로 투약 기록을 조회한다.
- 약 이름, 실제 복용 시각, 수량, 메모를 표시한다.
- 삭제되지 않은 기록만 일반 화면에 표시한다.
- 일일 경계와 정렬은 한국 시간을 기준으로 한다.

### 3.5 오류와 빈 상태

다음 상태를 구분한다.

- 최초 로딩
- 데이터 없음
- 환경변수 설정 오류
- 네트워크 연결 실패
- Supabase 조회 실패
- 저장·수정·삭제 실패

오류 때문에 화면에 데이터가 없을 때 이를 “기록 없음”으로 오해하게 표현하지 않는다.

## 4. P1 요구사항

### 4.1 홈 정보

- 약별 마지막 실제 복용 시각과 수량
- 약별 오늘 누적 복용 수량
- 오늘 일정별 `기록 있음 / 아직 기록 없음`

`아직 기록 없음`은 미복용 판정이 아니다. 지각, 누락, 추가 복용을 자동 판정하지 않는다.

### 4.2 상세 투약 기록

- 사용자가 실제 복용 시각을 입력하거나 수정할 수 있다.
- 메모를 입력할 수 있다.
- 일정에서 시작한 복용과 일정 없는 추가 복용을 구분한다.
- 추가 복용을 입력해도 앱은 처방 적정성을 판단하지 않는다.

### 4.3 기록 수정과 삭제

- 수량, 실제 시각, 메모를 수정할 수 있다.
- 삭제는 즉시 물리 삭제하지 않고 `deleted_at`을 기록한다.
- 삭제 직후 실행 취소를 제공한다.
- 설정 변경과 기록 수정은 구분한다.

### 4.4 상태 수정과 삭제

- 날짜를 선택해 하루 상태를 조회한다.
- 기존 기록을 수정할 수 있다.
- 삭제 전 확인한다.

### 4.5 약과 스케줄 설정

- 약 추가, 이름·단위·수량 선택지 수정, 활성/비활성화
- 일정 추가, 예정 시각·기본 수량 수정, 활성/비활성화
- 사용 이력이 있는 약과 일정은 물리 삭제하지 않는다.
- 변경된 설정은 새 기록에만 적용하고 과거 기록을 바꾸지 않는다.

### 4.6 날짜별 타임라인

- 선택한 한국 날짜의 투약 기록과 상태 기록을 함께 표시한다.
- 투약은 실제 시각 순으로 정렬한다.
- 하루 상태는 해당 날짜의 별도 섹션으로 표시한다.
- 통계, 추이, 의학적 해석은 표시하지 않는다.

### 4.7 접근성

- 최소 터치 영역 48px
- 시스템 글자 확대 대응
- 키보드만으로 모든 기능 사용 가능
- 화면 낭독기용 이름·상태·오류 연결
- 색상 외 텍스트로 상태 표현
- 저장 중과 비활성 상태를 보조기술에 전달

### 4.8 투약 일정 알림 — 완료

- 설정 화면에서 현재 기기의 알림을 `켜기 / 테스트 / 끄기` 할 수 있다.
- 알림 권한과 Push 구독은 브라우저가 기기별로 관리하며 로그인, 접근 코드, 기기 승인 절차로 사용하지 않는다.
- 알림 발송 대상은 활성 약의 활성 일정이다.
- 예정 시각부터 해당 한국 날짜가 끝나기 전까지 같은 일정의 삭제되지 않은 투약 기록이 없으면 5분 간격으로 알림 발송을 시도한다.
- 같은 일정의 투약 기록이 생기면 새 반복 알림을 만들지 않고, 아직 전송되지 않은 해당 일정 알림도 건너뛴다.
- Supabase Cron은 매분 발송 대상을 확인하고, Vercel의 보호된 발송 API가 Web Push 전송을 수행한다.
- 같은 기기·일정·5분 알림 회차의 발송은 한 번만 생성한다.
- 반복 알림은 같은 notification tag를 갱신하고 지원하는 기기에는 다시 알림·진동을 요청해 알림 항목이 계속 쌓이지 않게 한다.
- 알림을 누르면 해당 약과 일정이 선택된 투약 기록 화면으로 이동한다.
- iPhone/iPad에서는 iOS/iPadOS 16.4 이상에서 Safari의 `홈 화면에 추가`로 설치한 앱을 열어 알림을 허용한다.
- 권한 요청은 사용자가 알림 켜기 버튼을 누른 동작 안에서만 시작한다.
- 알림 문구는 기록 확인을 안내할 뿐 미복용, 지연, 추가 복용 필요를 판단하거나 지시하지 않는다.
- 네트워크, 운영체제의 집중 모드·절전 설정과 푸시 서비스 상태에 따라 알림이 늦거나 도착하지 않을 수 있음을 설정 화면에 표시한다.

## 5. 제외 요구사항

- 인증, 접근 코드, 기기 승인
- 브라우저 로컬 영구 저장과 오프라인 큐
- 백업, 복원, CSV/PDF, 데이터 가져오기
- 미복용·지연 복용 판정
- 알림의 정시 도착 또는 필수 도착 보장
- 통계, 그래프, 추이
- 역할, 초대, 권한별 공유
- AI·의료적 판단·복약 권고

## 6. P0 수용 기준

- 빈 Supabase 설정으로 운영 모드를 실행하면 설정 오류가 보인다.
- 저장 실패 시 완료 메시지나 가짜 로컬 기록이 남지 않는다.
- 제출 버튼 연타와 동일 요청 재시도로 투약 로그가 하나만 생긴다.
- 자정 전후 기록이 한국 날짜에 맞게 조회된다.
- 약이나 일정 설정을 바꿔도 기존 로그의 표시 정보가 달라지지 않는다.
- Playwright는 실제 Supabase 없이 메모리 mock DB로 핵심 흐름을 검증한다.
