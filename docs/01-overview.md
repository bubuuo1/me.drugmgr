# 투약 관리 앱 - 프로젝트 개요

## 1. 목적

`me.drugmgr`는 근무력증 환자의 실제 투약과 하루 상태를 가족이 휴대폰에서 빠르게 기록하고 함께 확인하는 개인용 웹 앱이다.

핵심 목적은 다음 두 가지다.

1. 실제로 복용한 약, 수량, 시각을 빠르고 정확하게 남긴다.
2. 여러 가족 기기에서 같은 최신 기록을 확인한다.

이 앱은 의료기기나 처방 도구가 아니다. 복용량을 결정하거나 처방 변경을 권고하지 않으며, 응급 대응 수단으로 사용하지 않는다.

## 2. 확정된 운영 모델

- 가족 구성원은 Vercel 프로젝트의 같은 URL에 직접 접속한다.
- 로그인, 접근 코드, 기기 승인은 사용하지 않는다.
- URL에 접속한 모든 사람은 하나의 가족 데이터셋을 함께 사용한다.
- Supabase가 유일한 영구 저장소다.
- 앱은 온라인 상태에서만 조회·저장할 수 있다.
- localStorage, IndexedDB, 쿠키 기반 데이터 저장, 오프라인 큐를 사용하지 않는다.
- 알림을 켠 기기에는 브라우저가 관리하는 Web Push 권한과 구독이 남는다. 이는 로그인, 기기 승인, 앱 데이터의 로컬 저장이 아니다.
- GitHub 저장소는 `bubuuo1/me.drugmgr`다.
- Vercel 배포는 새 계정의 `me-drugmgr` 프로젝트와 Git Integration이 담당한다.

URL은 접근 제어 수단이 아니다. 이 앱은 해당 위험을 받아들인 소규모 가족 사용으로 범위를 제한한다.

## 3. 관리 대상

reset 스키마의 초기 관리 대상은 다음 약이다.

- 메스티논: 하루 여러 번 복용 가능
- 소론도: 설정된 일정에 따라 복용
- 셉트린정: 복용 여부를 횟수로 기록

초기 값은 이후 설정에서 변경할 수 있다. 약 이름, 단위, 수량 선택지, 기본 수량, 일정은 설정 데이터다. 실제 투약 기록은 설정과 분리하고 당시의 표시 정보와 예정 정보를 보존한다. 설정 변경이 과거 기록의 의미를 바꾸면 안 된다.

## 4. 핵심 사용자 여정

### 투약 기록

1. 앱을 연다.
2. 홈에서 약 또는 오늘 일정을 선택한다.
3. 복용 수량을 선택한다.
4. 앱이 실제 복용 시각을 현재 시각으로 채운다.
5. Supabase 저장이 성공할 때까지 기다린다.
6. 성공 메시지와 방금 기록한 내용을 확인한다.

P1에서는 실제 시각과 메모를 수정해 저장할 수 있고, 일정과 연결되지 않은 추가 복용도 구분해 기록한다.

### 일정 알림

1. 설정 화면에서 현재 기기의 알림을 직접 허용한다.
2. 테스트 알림으로 수신 가능 여부를 확인한다.
3. 약별로 필요한 복용·알림 시간을 여러 개 등록하고 Supabase Cron이 각 활성 시간을 매분 확인한다.
4. 각 예정 시각부터 그날 같은 일정의 투약 기록이 생길 때까지 5분마다 Vercel 발송 API를 통해 알림 전송을 시도한다.
5. 해당 시간을 끄거나 삭제하거나 투약 기록을 저장하면 서버 발송 전 다시 확인해 반복을 중단하고, 현재 기기에 표시된 같은 일정 알림도 닫는다.
6. 알림을 누르면 해당 투약 기록 화면을 연다.

알림은 기록 확인을 돕는 보조 기능이다. 브라우저, 네트워크, 집중 모드, 절전 설정에 따라 늦게 도착하거나 도착하지 않을 수 있으며, 앱은 이를 미복용이나 지연 복용으로 판정하지 않는다.

### 상태 기록

1. 홈에서 오늘 상태를 선택한다.
2. 피로, 근력, 호흡, 눈 증상과 메모를 입력한다.
3. Supabase 저장 성공을 확인한다.

P1에서는 날짜를 선택해 상태를 수정하거나 삭제하고 투약 기록과 같은 타임라인에서 확인한다.

## 5. 제품 원칙

- 기록 정확성을 기능 수보다 우선한다.
- 저장 요청은 반드시 `await`하고 성공 확인 전에는 완료로 표시하지 않는다.
- 같은 동작의 반복 탭이나 네트워크 재시도로 중복 기록이 생기지 않게 한다.
- 날짜 구분은 `Asia/Seoul`의 달력 날짜를 기준으로 한다.
- 예정 시간과 실제 복용 시간은 별도 값이다.
- 기록이 없다는 사실을 미복용으로 판정하지 않는다.
- 푸시 알림의 수신 여부나 시각을 복용 사실의 근거로 사용하지 않는다.
- 약 설정 변경이 과거 기록을 자동 변경하지 않는다.
- 색상만으로 상태를 구분하지 않는다.
- 의료적 판단과 복약 지시는 제공하지 않는다.

## 6. 구현 우선순위

### P0 — 데이터 정확성과 운영 기반

- Supabase 단일 저장소 전환
- 온라인 로딩·실패·재시도 상태
- 쓰기 작업의 `await` 및 오류 전파
- 중복 저장 방지 키와 제약
- 일정 연결 정확성
- 과거 기록 무결성
- 한국 날짜와 UTC 시각 저장 규칙
- P0/P1을 수용하는 새 스키마
- 실제 Supabase를 사용하지 않는 Playwright 품질 검사

기존 Supabase 데이터는 보존하거나 마이그레이션하지 않는다.

### P1 — 일상 사용 기능

- 홈의 마지막 복용, 오늘 누적, 일정 상태
- 실제 시각·메모, 일정 복용·추가 복용
- 기록 수정, soft delete, 실행 취소
- 날짜별 상태 수정·삭제
- 약별 여러 복용·알림 시간의 연속 등록·수정·끄기·삭제
- 날짜별 투약+상태 타임라인
- 기기별 일정 알림 켜기·테스트·끄기와 활성 일정 Web Push(완료)
- 전체 화면의 접근성 완성

## 7. 명시적 제외

P0와 P1 모두 다음을 구현하지 않는다.

- 인증, 접근 코드, 기기 승인
- 오프라인 조회·기록·동기화와 로컬 영구 저장
- 백업·복원과 데이터 가져오기
- 미복용·지연 복용 판정과 알림의 정시·필수 도착 보장
- 통계, 그래프, 추이 또는 상관관계 분석
- CSV/PDF 내보내기와 의료진용 자동 보고서
- 역할별 권한과 초대·공유 관리
- AI 분석, 위험도 판단, 진단, 복용량·처방 추천

## 8. 의료 안전 원칙

- 앱은 사용자가 입력한 사실만 기록한다.
- 상태 점수를 근거로 진단하거나 약 복용을 안내하지 않는다.
- 누락된 것으로 보이는 일정에 대해 임의 복용을 권하지 않는다.
- 호흡이나 삼킴이 심하게 악화되는 등 응급 상황에서는 앱 기록보다 사용자가 의료진과 정한 대응과 응급 연락을 우선해야 한다.
- 삭제·수정은 사용자의 명시적 동작으로만 수행하고 P1의 투약 로그 soft delete는 되돌릴 수 있게 한다.
