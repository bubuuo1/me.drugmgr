# 보안 설계

## 1. 로그인 없음

사용자 경험을 단순하게 하기 위해 로그인 기능을 사용하지 않는다.

## 2. 중요한 문제

로그인이 없더라도 Supabase 데이터베이스를 인터넷에 그대로 공개해서는 안 된다.

Supabase의 RLS(Row Level Security)를 사용한다.

## 3. 초기 방향

앱 하나에서 사용하는 개인 데이터라는 전제하에 접근 정책을 설계한다.

단순히 모든 테이블에:

SELECT *
INSERT *
UPDATE *
DELETE *

권한을 무조건 공개하는 방식은 사용하지 않는다.

## 4. 데이터 접근

가능하면 앱에서 필요한 작업만 허용한다.

예:

- 투약 기록 추가
- 투약 기록 조회
- 투약 기록 수정
- 상태 기록 추가
- 상태 기록 조회

## 5. API Key

Supabase의 공개용 anon/publishable key만 클라이언트에 사용한다.

service role key는 절대 모바일 클라이언트에 포함하지 않는다.

## 6. 추가 보안 검토

로그인 없이 개인 데이터가 서버에 저장되므로 향후 다음 방식을 검토할 수 있다.

- 기기별 비밀 토큰
- 앱 설치별 식별자
- Edge Function을 통한 제한된 API
- 별도 인증 방식

초기 구현에서 보안 수준과 편의성을 함께 검토한다.

## 7. 개인정보

건강 관련 기록이 포함될 수 있으므로 불필요한 개인정보는 저장하지 않는다.

사용자 이름, 주민등록번호 등의 개인정보는 저장하지 않는다.
