# 상태 기록

## 1. 목적

투약 기록과 함께 하루의 주관적 상태를 간단히 기록한다. 상태 기록은 사용자가 그날의 상황을 회상하기 위한 일기이며 진단, 중증도 판정, 복약 결정에 사용하지 않는다.

## 2. 날짜 규칙

- 상태는 복약 공간별로 `Asia/Seoul` 달력 날짜 기준 하루 한 건이다.
- 날짜는 순간 시각이 아니라 `YYYY-MM-DD` 값으로 저장한다.
- 같은 날짜를 다시 저장하면 새 행을 만들지 않고 기존 행을 수정한다.
- 같은 복약 공간의 여러 구성원이 같은 날짜를 열면 Supabase의 같은 기록을 사용한다.
- 관계없는 복약 공간은 같은 날짜에도 서로 다른 행을 사용하며 RLS로 격리한다.

## 3. 기본 항목

### 피로

- 좋음
- 보통
- 나쁨

### 근력

- 좋음
- 보통
- 나쁨

### 호흡

- 편안함
- 평소와 다름

### 눈 증상

- 없음
- 있음

### 메모

짧은 자유 입력이다. 예: `오후부터 평소보다 피곤했음`.

각 값은 선택하지 않을 수 있으며, 앱은 선택 결과로 점수를 계산하지 않는다.

## 4. P0 저장 동작

1. 오늘 한국 날짜를 계산한다.
2. 기존 오늘 기록을 조회한다.
3. 사용자가 항목과 메모를 입력한다.
4. `care_space_id + date` unique 제약을 기준으로 insert 또는 update한다.
5. DB 성공 응답 후 완료를 표시한다.

요청 실패 시 로컬 사본을 만들거나 성공으로 표시하지 않는다.

## 5. P1 수정과 삭제

- 사용자가 날짜를 선택해 기존 상태를 연다.
- 소유자와 보호자는 상태를 작성·수정·삭제할 수 있고 조회자는 읽기만 가능하다.
- 항목과 메모를 수정한다.
- 삭제 전 대상 날짜와 삭제 결과를 확인한다.
- 삭제 성공 후 해당 날짜를 다시 조회한다.
- 투약+상태 타임라인에서 같은 날짜의 상태를 함께 표시한다.

상태 기록 삭제는 투약 로그를 변경하지 않는다.

## 6. 다기기 동작

- 저장 전후 최신 상태를 Supabase에서 조회한다.
- 권한이 있는 두 구성원이 같은 날짜를 수정하면 마지막으로 성공한 DB 값이 최신 값이다.
- 화면은 저장 후 반환된 최신 값을 다시 표시한다.
- 로컬 병합, 오프라인 충돌 해결, 편집 잠금은 제공하지 않는다.

## 7. 의료 안전

- `평소와 다름`은 사용자의 주관적 기록이며 앱이 응급 여부를 판정하지 않는다.
- 상태 화면은 앱이 의료 판단 또는 응급 대응을 제공하지 않는다고 알린다.
- 심한 호흡·삼킴 악화 등 응급 상황에서는 앱 입력보다 사용자가 의료진과 정한 대응과 응급 연락을 우선한다.
- 상태에 따라 약 복용량을 바꾸거나 추가 복용을 권고하지 않는다.

## 8. 제외 범위

- 상태 점수와 위험도 계산
- 주·월간 그래프와 추이
- 투약과 증상의 상관관계 분석
- 리마인더와 푸시 알림
- AI 요약과 의료진용 자동 보고서
- 검증된 임상 척도의 임의 변형
