# 디자인 시스템 - 모바일 UI 및 접근성

## 0. 디자인 베이스

이 문서는 모든 화면 디자인의 기준이다. 시각 언어는 `DESIGN-airbnb.md`의 Airbnb 분석을 바탕으로 한다.

- 깨끗한 흰 캔버스와 하나의 브랜드 강조색
- 부드러운 라운딩과 넉넉한 여백
- 큰 텍스트 라벨과 넓은 터치 영역
- 플랫한 표면과 한 단계의 그림자
- 모바일 세로 화면 우선, 최대 폭 `28rem`

빠르게 기록하는 경험을 우선하되 저장 정확성과 접근성을 희생하지 않는다.

## 1. 상호작용 원칙

- 화면당 핵심 동작은 1~2개로 제한한다.
- 저장 중에는 입력과 제출을 잠그고 진행 상태를 텍스트로 알린다.
- DB 응답 전에는 “완료”로 표시하거나 홈으로 이동하지 않는다.
- 오류, 기록 있음, 아직 기록 없음은 색상과 텍스트를 함께 사용한다.
- `아직 기록 없음`을 `미복용` 또는 `누락`이라고 표현하지 않는다.
- 네트워크 오류 화면은 로컬 저장이나 나중 동기화를 암시하지 않는다.
- 사용자가 휴대폰 글자 크기를 확대해도 동작과 내용이 잘리지 않는다.

## 2. 디자인 토큰

토큰은 `app/globals.css`의 CSS 변수와 `@theme inline`에서만 정의한다. 컴포넌트에서 색상을 하드코딩하지 않는다.

### 2.1 색상

| 토큰 | 값 | 용도 |
|---|---:|---|
| `primary` | `#ff385c` | 주요 CTA |
| `primary-active` | `#e00b41` | 누름 상태 |
| `primary-disabled` | `#ffd1da` | 비활성 CTA |
| `ink` | `#222222` | 제목·본문 |
| `body` | `#3f3f3f` | 보조 본문 |
| `muted` | `#6a6a6a` | 날짜·보조 라벨 |
| `muted-soft` | `#929292` | 비활성 보조 텍스트 |
| `canvas` | `#ffffff` | 기본 배경 |
| `surface-soft` | `#f7f7f7` | 비활성 필드·보조 표면 |
| `surface-strong` | `#f2f2f2` | 아이콘 버튼 표면 |
| `hairline` | `#dddddd` | 경계선 |
| `hairline-soft` | `#ebebeb` | 구분선 |

보통 텍스트는 WCAG AA 4.5:1, 큰 텍스트는 3:1 이상을 유지한다. `primary` 위 흰색 CTA 라벨은 20px/700 이상의 큰 텍스트를 사용한다.

### 2.2 타이포그래피

```css
'Airbnb Cereal VF', Circular, Inter, -apple-system, system-ui, Roboto, 'Helvetica Neue', sans-serif
```

| 토큰 | 크기/가중치 | 용도 |
|---|---|---|
| `display` | 24px/700 | 화면 제목 |
| `title` | 20px/700 | 섹션 제목 |
| `button-xl` | 20px/700 | 홈 CTA |
| `button-lg` | 20px/600 | 수량·상태 선택 |
| `button-md` | 18px/600 | 저장·보조 버튼 |
| `body` | 18px/400 | 기본 본문 |
| `body-sm` | 16px/400 | 날짜·시간·메모 |
| `caption` | 14px/500 | 필드 라벨·보조 텍스트 |

폰트 크기는 `rem` 등 유동 단위를 사용한다.

### 2.3 형태와 간격

| 토큰 | 값 |
|---|---:|
| `rounded-sm` | 8px |
| `rounded-md` | 14px |
| `rounded-lg` | 20px |
| `rounded-xl` | 32px |
| `rounded-full` | 9999px |

- 주요 선택 버튼은 pill 형태다.
- 주요 버튼 높이는 64~72px, 모든 터치 영역은 최소 48px다.
- 화면 안쪽 여백은 16~24px, 주요 버튼 사이는 24px 이상이다.
- 떠 있는 메뉴나 대화상자에만 단일 섀도우 티어를 사용한다.

## 3. 공통 상태 컴포넌트

### 3.1 로딩

- 최초 로딩은 `aria-busy="true"`와 “기록을 불러오는 중” 텍스트를 제공한다.
- 저장 버튼은 “저장 중…”으로 바뀌고 비활성화된다.
- 기존 데이터가 없는 것처럼 빈 화면을 먼저 보여주지 않는다.

### 3.2 오류

오류 카드는 오류 종류, 실패한 작업, 재시도 버튼을 포함한다.

- 설정 오류: “Supabase 연결 설정이 필요합니다.”
- 조회 오류: “기록을 불러오지 못했습니다. 다시 시도해 주세요.”
- 저장 오류: “저장하지 못했습니다. 기록은 추가되지 않았습니다.”
- 연결 오류: “인터넷 연결이 필요합니다.”

오류 카드에는 localStorage 저장, 오프라인 보관, 자동 동기화를 암시하는 문구를 쓰지 않는다.

### 3.3 완료

완료 알림 예:

> 메스티논 2정 · 16:05 기록 완료

체크 아이콘에만 의미를 의존하지 않고 전체 문장을 라이브 영역으로 알린다. 삭제 실행 취소는 P1에서 제한 시간과 함께 제공한다.

### 3.4 빈 상태

- 정상 조회 후 데이터가 없을 때만 “이 날짜의 기록이 없습니다.”를 표시한다.
- 일정에 기록이 없으면 “아직 기록 없음”이라고 쓴다.
- 빈 상태를 의료적 미복용 판정으로 표현하지 않는다.

## 4. 홈 화면

### P0

Supabase에서 조회한 활성 약마다 큰 기록 버튼을 표시하고 그 아래에 `오늘 상태`, `기록 확인`을 둔다. reset 스키마의 초기 약은 메스티논, 소론도, 셉트린정이지만 목록을 하드코딩하지 않는다.

수량 선택지가 있는 약은 `약 이름 기록`, 선택지가 빈 약은 `복용함 기록`처럼 동작을 명확히 표현한다. 주요 약 기록 버튼은 `primary`, 상태와 기록 확인은 아웃라인 스타일을 사용한다.

### P1

홈의 단순함을 유지하면서 약 카드 안에 다음을 표시한다.

- 마지막 복용: `16:05 · 2정` 또는 `기록 없음`
- 오늘 누적: `총 5정`
- 일정 상태: `12:00 · 기록 있음` 또는 `16:00 · 아직 기록 없음`

일정 상태는 텍스트를 반드시 포함하며 리마인더, 경고음, 미복용 판정을 만들지 않는다.

매일 쓰는 기록 동선을 우선해 홈은 `빠른 투약 기록` → `오늘 상태` → `기록 확인` → `오늘 예정` → `약·일정 관리` 순서로 배치한다. 설정 진입점은 헤더에 두지 않는다.

## 5. 투약 기록 화면

### P0

- 약 이름
- “몇 정 드셨나요?”
- 약 설정의 수량 선택지와 `[직접 입력]`, 또는 선택지가 빈 약의 `[복용함]`
- 일정에서 진입한 경우 예정 시각
- 저장 진행·성공·실패 상태

수량 선택은 한 번의 저장 요청을 만든다. 요청 중 모든 수량 버튼을 비활성화하고 같은 요청 ID를 재사용해 중복을 방지한다.

직접 입력은 필드 라벨, 허용 범위, 단위, 검증 오류를 제공한다.

### P1

- 실제 복용 날짜·시각 편집
- 메모
- 연결된 일정 표시
- “추가 복용 기록” 진입점

추가 복용은 일정이 없음을 명시하지만, 적절성 판단이나 복용 권고를 표시하지 않는다.

## 6. 상태 기록 화면

- 피로: `[좋음] [보통] [나쁨]`
- 근력: `[좋음] [보통] [나쁨]`
- 호흡: `[편안함] [평소와 다름]`
- 눈 증상: `[없음] [있음]`
- 기타 메모
- 저장

각 그룹은 `fieldset`과 `legend` 또는 동등한 접근 가능 구조를 사용한다. P1에서는 날짜 선택, 기존 기록 수정, 삭제를 제공한다.

화면에는 앱이 의료 판단이나 응급 대응을 제공하지 않는다는 짧은 안내를 둔다. 상태 삭제는 실행 전 확인한다.

## 7. 기록·타임라인 화면

### P0

- 날짜 헤더와 이전/다음/오늘 이동
- 약별 실제 복용 시각, 수량, 메모
- 정상 빈 상태와 조회 오류 구분

### P1

- 실제 복용 시각 순의 투약 목록
- 같은 날짜의 상태 기록 섹션
- 투약 기록 수정·삭제
- 삭제 직후 실행 취소

하루 총량은 홈의 오늘 정보로만 제공한다. 기록 화면에 주·월간 통계, 그래프, 추이 해석을 추가하지 않는다.

## 8. 약·스케줄 설정 화면 — P1

- 약 추가, 이름·단위·수량 선택지 편집, 활성/비활성화
- 일정 추가, 예정 시각, 기본 수량, 활성/비활성화
- 사용 이력이 있는 약·일정에는 물리 삭제 버튼을 제공하지 않는다.
- 설정 변경 전 “과거 기록은 변경되지 않습니다.”를 설명한다.

## 9. 접근성 완료 조건

- 320px 폭과 200% 글자 확대에서 가로 스크롤 없이 핵심 동작 가능
- 키보드 포커스가 시각적으로 명확함
- 대화상자 포커스 이동·복귀와 Escape 닫기 지원
- 버튼, 날짜 이동, 선택 상태에 접근 가능한 이름 제공
- 입력 오류를 필드와 `aria-describedby`로 연결
- 로딩·완료·오류를 적절한 라이브 영역으로 전달
- 색상과 아이콘 없이도 기록 상태 이해 가능
- 모션 감소 설정 존중

## 10. 다크 모드

P0/P1 범위가 아니다. 향후 도입 여부와 무관하게 모든 색상은 토큰만 사용한다.
