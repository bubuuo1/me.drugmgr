# 디자인 시스템 - 모바일 UI 및 접근성

> 이 문서는 화면·상호작용·접근성의 정본이다. 기능과 권한은 [02 기능 요구사항](02-requirements.md), 원본 시각 분석은 [비규범 Airbnb 참고 자료](../DESIGN-airbnb.md)를 따른다.

## 0. 디자인 베이스

이 문서는 모든 화면 디자인의 기준이다. 시각 언어는 `DESIGN-airbnb.md`의 Airbnb 분석을 참고하되, 두 문서의 값이 다르면 이 문서와 `app/globals.css`를 따른다.

- 깨끗한 흰 캔버스와 하나의 브랜드 강조색
- 부드러운 라운딩과 넉넉한 여백
- 큰 텍스트 라벨과 넓은 터치 영역
- 플랫한 표면과 한 단계의 그림자
- 모바일 세로 화면 우선, 최대 폭 `28rem`

빠르게 기록하는 경험을 우선하되 저장 정확성과 접근성을 희생하지 않는다.

## 1. 상호작용 원칙

- 화면당 핵심 동작은 1~2개로 제한한다.
- 저장 중에는 입력과 제출을 잠그고 진행 상태를 텍스트로 알린다.
- DB 응답 전에는 “완료”로 표시하거나 홈으로 이동하지 않는다.
- 오류와 기록 완료 상태는 색상과 텍스트를 함께 사용한다.
- 미완료 일정을 `미복용` 또는 `누락`이라고 표현하지 않는다.
- 네트워크 오류 화면은 실패한 쓰기의 로컬 저장이나 나중 자동 전송을 암시하지 않는다.
- 알림 권한은 사용자가 설정 화면의 버튼을 누른 직후에만 요청한다.
- 알림 도착은 보조 기능이며 정시 도착을 보장하는 문구를 사용하지 않는다.
- 현재 선택한 복약 공간과 사용자 역할을 기록 화면에서 식별할 수 있게 유지한다.
- 복약 공간을 바꾸면 이전 사람의 데이터를 즉시 지우고 새 공간의 로딩 상태를 먼저 표시한다.
- 권한이 없는 쓰기 동작은 숨기거나 비활성화하고 이유를 텍스트로 설명한다. DB의 RLS 거부도 정상 오류로 처리한다.
- 사용자가 휴대폰 글자 크기를 확대해도 동작과 내용이 잘리지 않는다.

## 2. 디자인 토큰

앱 화면 토큰은 `app/globals.css`의 CSS 변수와 `@theme inline`에서만 정의한다. 컴포넌트에서 색상을 하드코딩하지 않는다. CSS 변수를 해석하지 못하는 Web App Manifest와 Next viewport 메타데이터는 플랫폼 예외로 같은 토큰 값을 리터럴로 제공하며, manifest E2E에서 값과 제공 여부를 검증한다.

### 2.3 형태와 간격

| 토큰 | 값 |
|---|---:|
| `rounded-sm` | 0.375rem, 기본 16px에서 6px |
| `rounded-md` | 0.5rem, 기본 16px에서 8px |
| `rounded-lg` | 0.625rem, 기본 16px에서 10px |

- 주요 선택 버튼은 pill 형태다.
- 주요 버튼 높이는 64~72px, 모든 터치 영역은 최소 48px다.
- 화면 안쪽 여백은 16~24px, 주요 버튼 사이는 24px 이상이다.
- 떠 있는 메뉴나 대화상자에만 단일 섀도우 티어를 사용한다.

## 3. 공통 상태 컴포넌트

### 3.1 로딩

- 최초 로딩은 `aria-busy="true"`와 “기록을 불러오는 중” 텍스트를 제공한다.
- 최초 조회가 끝난 뒤의 백그라운드 재확인은 기존 화면을 유지하며 최초 로딩 화면으로 되돌아가지 않는다.
- 저장 버튼은 “저장 중…”으로 바뀌고 비활성화된다.
- 기존 데이터가 없는 것처럼 빈 화면을 먼저 보여주지 않는다.

### 3.2 오류

오류 카드는 오류 종류, 실패한 작업, 재시도 버튼을 포함한다.

- 설정 오류: “Supabase 연결 설정이 필요합니다.”
- 인증 오류: “로그인이 만료되었습니다. 다시 로그인해 주세요.”
- 권한 오류: “이 복약 공간에서 변경할 권한이 없습니다.”
- 조회 오류: “기록을 불러오지 못했습니다. 다시 시도해 주세요.”
- 저장 오류: “저장하지 못했습니다. 기록은 추가되지 않았습니다.”
- 연결 오류: “인터넷 연결이 필요합니다.”

오류 카드에는 localStorage 저장, 오프라인 보관, 실패한 쓰기의 나중 자동 재전송을 암시하는 문구를 쓰지 않는다.

### 3.3 완료

완료 알림 예:

> 메스티논 2정 · 16:05 기록 완료

체크 아이콘에만 의미를 의존하지 않고 전체 문장을 라이브 영역으로 알린다. 삭제 실행 취소는 P1에서 제한 시간과 함께 제공한다.

### 3.4 빈 상태

- 정상 조회 후 데이터가 없을 때만 “이 날짜의 기록이 없습니다.”를 표시한다.
- 일정에 기록이 없으면 별도 상태 문구를 반복하지 않는다. 쓰기 권한이 있을 때만 “기록하기” 동작을 표시한다.
- 빈 상태를 의료적 미복용 판정으로 표현하지 않는다.

## 4. 홈 화면

로그인하지 않은 사용자는 약이나 기록 대신 Google 로그인 화면을 본다. 로그인 후 주요 화면에는 `첫 화면 / 복용기록 / 환경설정` 하단 내비게이션을 제공하고 같은 동작의 상단 `첫 화면` 링크를 중복 표시하지 않는다. `복용기록`과 `환경설정` 탭은 별도 시각적 화면 제목 없이 바로 핵심 콘텐츠를 표시하되 접근성용 H1은 유지한다. 가족 공유처럼 환경설정에서 들어가는 하위 화면에만 명시적인 부모 화면 복귀 링크를 둔다. 앱을 새로 열면 소유자의 복약 공간을 기본 기록 대상으로 선택하고, 알림 딥링크의 명시적 공간은 우선한다. 공간 전환·가족 관리·로그아웃은 환경설정에 두며, 기록 화면에는 현재 기록 대상 이름과 역할을 짧게 유지한다.

### P0

선택한 복약 공간의 `오늘 예정` 일정을 첫 콘텐츠로 표시한다. 이어서 조회한 활성 약마다 큰 기록 버튼을 표시하고 그 아래에 `오늘 상태`, `복용기록 확인`을 둔다. 활성 약이 없는 공간에서는 소유자와 보호자에게 약 설정 진입점을 제공하고 목록을 하드코딩하지 않는다.

수량 선택지가 있는 약은 `약 이름 기록`, 선택지가 빈 약은 `복용함 기록`처럼 동작을 명확히 표현한다. 주요 약 기록 버튼은 `primary`, 상태와 복용기록 확인은 아웃라인 스타일을 사용한다.

약 카드의 주요 버튼이 아직 기록 없는 일정을 가리키면 `16:00 예정 기록`처럼 예정 시각을 포함한다. 아직 기록 없는 일정이 없을 때만 `추가 복용 기록` 또는 `복용 기록`으로 표시한다. `오늘 예정`의 각 일정도 별도 기록 동작을 제공하며 현재 시각만으로 연결 일정을 자동 선택하지 않는다.

### P1

홈의 단순함을 유지하면서 약 카드 안에 다음을 표시한다.

- 마지막 복용: `16:05 · 2정` 또는 `기록 없음`
- 오늘 누적: `총 5정`
- 일정 상태: 완료 일정의 `12:00 · 기록 있음`; 미완료 일정은 예정 시각·약 이름과 권한별 `기록하기` 동작

완료 일정은 상태 텍스트를 포함한다. 미완료 일정은 별도 상태 문구를 반복하지 않으며 알림 수신 여부와 관계없이 미복용 판정이나 경고로 표현하지 않는다.

매일 쓰는 예정 확인과 기록 동선을 우선해 홈은 별도 시각적 제목·설명 블록 없이 `오늘 예정`을 첫 화면에 표시한다. `빠른 투약 기록`은 접근성용 H1으로만 제공하고, `오늘 예정` → 약 카드 → `오늘 상태` → `복용기록 확인` → `약·일정 관리` 순서로 배치한다. 설정 진입점은 헤더에 두지 않는다. 보호자에게는 약·일정 관리와 투약·상태 기록 동작을 제공하고, 조회자에게는 읽기 전용 상태를 명확히 표시한다.

## 5. 투약 기록 화면

### P0

- 약 이름
- “몇 정 드셨나요?”
- 약 설정의 수량 선택지와 `[직접 입력]`, 또는 선택지가 빈 약의 `[복용함]`
- 일정에서 진입한 경우 예정 시각
- 저장 진행·성공·실패 상태

수량 선택은 한 번의 저장 요청을 만든다. 요청 중 모든 수량 버튼을 비활성화하고 같은 요청 ID를 재사용해 중복을 방지한다.

직접 입력은 필드 라벨, 허용 범위, 단위, 검증 오류를 제공한다.

### P1

- 실제 복용 날짜·시각 편집
- 메모
- 연결된 일정 표시
- “추가 복용 기록” 진입점

추가 복용은 일정이 없음을 명시하지만, 적절성 판단이나 복용 권고를 표시하지 않는다.

## 6. 상태 기록 화면

- 피로: `[거의 없음] [조금 피곤함] [매우 피곤함]`
- 근력: `[평소와 비슷함] [조금 약함] [많이 약함]`
- 호흡: `[평소와 같음] [평소와 다름]`
- 눈 증상: `[증상 없음] [증상 있음]`
- 기타 메모
- 저장

표시 문구와 DB 저장값의 매핑은 [05 상태 기록](05-status.md)을 따른다. 각 그룹은 `fieldset`과 `legend` 또는 동등한 접근 가능 구조를 사용한다. P1에서는 날짜 선택, 기존 기록 수정, 삭제를 제공한다. 상태 선택이나 메모가 하나도 없는 새 행은 저장하지 않고, 기존 내용을 모두 지울 때는 삭제 동작을 사용한다.

각 화면 하단에 같은 면책 문구를 반복하지 않는다. 앱의 의료·응급 대응 비제공 안내는 로그인 또는 환경설정의 공통 정보에서 한 번에 확인할 수 있게 하고, 개별 화면에는 해당 동작과 직접 관련된 짧은 안전 문구만 둔다. 상태 삭제는 실행 전 확인한다.

날짜·시간 입력은 앱 디자인 토큰을 사용하는 공용 달력·시간 대화상자로 통일한다. 모바일에서는 하단 시트, 넓은 화면에서는 중앙 대화상자로 표시하고, 포커스 이동·복귀와 Escape 닫기를 지원한다. 실제 복용 날짜·시간처럼 두 값을 함께 표시하는 입력은 320~393px에서 동일한 전체 너비의 1열 카드로 배치하고 각 카드는 최소 64px 높이를 유지한다. 화면에는 짧은 `날짜`·`시간` 라벨을 쓰되 접근 가능한 이름과 대화상자 제목에는 `실제 복용 날짜`·`실제 복용 시간` 문맥을 보존한다. 날짜 필드 자체가 현재 선택 날짜를 표시하므로 같은 날짜를 별도 텍스트로 중복 표시하지 않으며, 달력 안에서는 선택 셀과 오늘을 텍스트·형태·색상으로 함께 구분한다. 시간은 임의의 `00:00`~`23:59` 값을 1분 단위로 입력할 수 있어야 한다. 공용 선택기는 실제 존재하는 `YYYY-MM-DD` 날짜와 유효한 시각만 생성하고, 저장 전 화면별 검증을 다시 거친다. 검증 오류는 입력과 연결된 텍스트로 표시한다.

## 7. 복용기록 확인·타임라인 화면

### P0

- 접근성용 화면 제목 뒤에 바로 이어지는 날짜 카드와 고정된 이전/오늘/다음 이동
- 기록 당시의 약 이름, 실제 복용 시각, 수량과 단위
- 메모가 있는 경우 함께 표시
- 정상 빈 상태와 조회 오류 구분

### P1

- 실제 복용 시각 순의 투약 목록
- 같은 날짜의 상태 기록 섹션
- 투약 기록 수정·삭제
- 삭제 직후 실행 취소

하루 총량은 홈의 오늘 정보로만 제공한다. 기록 화면에 주·월간 통계, 그래프, 추이 해석을 추가하지 않는다.

## 8. 약·스케줄 설정 화면 — P1

- 소유자와 보호자에게 편집 컨트롤을 제공한다. 조회자가 경로를 직접 열어도 설정을 변경할 수 없다.
- 약 추가, 이름·단위·수량 선택지 편집, 활성/비활성화
- 약별 `복용·알림 시간 (N개)`과 `알림 시간 추가`를 표시하고, 저장 후 입력 폼을 유지해 여러 시간을 연속 등록
- 각 시간의 예정 시각 수정과 `시간 끄기 / 시간 켜기 / 알림 시간 삭제`
- `약 삭제`는 확인 대화상자 후 처리하고, 등록 목록과 앞으로의 일정·알림에서 제외된다는 결과를 명시한다.
- 약이나 알림 시간을 삭제해도 과거 투약 기록의 약 이름·단위·실제 복용 시각·수량 스냅샷은 유지한다.

## 9. 투약 일정 알림 — P1

환경설정 화면에는 `투약 일정 알림` 카드를 둔다. 알림 카드는 모든 역할의 구성원에게 제공하고, 접근 가능한 각 복약 공간의 현재 기기 구독을 독립적으로 제어한다.

- 현재 기기의 상태를 `확인 중 / 설치 필요 / 미지원 / 설정 필요 / 권한 거부 / 꺼짐 / 켜짐 / 오류` 텍스트로 구분한다.
- 각 공간의 꺼짐 상태에는 `알림 받기`, 켜짐 상태에는 `테스트`와 `알림 끄기`를 제공한다.
- 권한 요청, 구독 등록, 테스트 발송, 해제 중에는 해당 버튼을 비활성화하고 진행 문구를 표시한다.
- 완료와 오류 문구는 각각 `role="status"`와 `role="alert"`로 전달한다.
- iPhone/iPad에서 홈 화면 앱이 아니면 Safari 공유 메뉴의 `홈 화면에 추가` 안내를 표시한다.
- 설명은 “등록한 각 복용·알림 시간부터 5분마다 반복하고, 해당 시간 기록·끄기·삭제 시 중단”으로 한정한다.
- “알림은 네트워크, 집중 모드와 절전 설정에 따라 늦게 도착할 수 있습니다.”라는 지연 가능성 안내를 항상 표시한다.
- 가족 기록 관리 요청 수락·양방향 전환과 알림 구독은 별개임을 설명하고, 알림을 켜는 동작은 승인 기기 등록으로 표현하지 않는다.

반복 push를 받으면 서비스 워커는 같은 공간·일정의 기존 표시를 닫고 새 알림으로 표시해 재진동을 요청한다. 일정 기록 저장·끄기·삭제 시 현재 기기의 같은 일정 알림도 닫는다. 알림을 누르면 해당 복약 공간, 약과 일정이 선택된 투약 기록 화면을 연다. 알림 본문과 화면은 복용을 지시하거나 미복용이라고 판단하지 않는다.

## 10. 가족 기록 관리 화면

- 환경설정의 가족 관리 항목에서 진입한다.
- 접근 가능한 복약 공간과 각 공간에서의 내 역할을 표시한다.
- 현재 공간의 구성원을 이름·역할과 함께 표시한다.
- 소유자에게만 관리하려는 가족의 이메일 입력, 관리 요청 만들기와 대기 요청 취소를 제공한다. 새 요청은 두 사람을 각각 상대 공간의 보호자로 추가하는 양방향 요청으로 고정하며 역할 선택기는 두지 않는다.
- 내 확인된 Google 이메일과 일치하는 대기 요청은 현재 선택 공간과 무관하게 수락하거나 거절할 수 있게 표시한다.
- 받은 요청의 수락 화면에는 내가 `owner`인 복약 공간만 선택지로 제공한다. 요청자가 선택한 내 공간을, 내가 요청자의 요청 공간을 각각 보호자로 조회·변경한다는 양방향 효과를 본문과 별도 동의 체크에 모두 표시한다. 공간 선택과 동의 전에는 수락 버튼을 비활성화한다.
- 관리 요청 이메일 발송 성공과 요청 저장 후 발송 실패를 구분하고, 대기 요청에 이메일 재발송 동작을 제공한다.
- 안내 메일은 임의 수신 주소로 보낼 수 있지만, 같은 이메일의 Google 계정 사용자가 자기 소유 공간을 선택하고 앱에서 양방향 권한에 명시적으로 동의한 뒤에만 두 사람을 각각 상대 공간의 보호자로 추가한다.
- `수락한 가족` 섹션은 선택한 기록 대상과 무관하게 양쪽 참여자에게 표시한다. 상대 이름, `서로 복약 기록 관리 중 / 내가 상대 기록만 관리 중 / 상대만 내 기록을 관리 중`, 접근 가능한 공간과 관리 진입점을 텍스트로 구분한다.
- 이미 수락된 과거 단방향 관계에는 반대 방향 권한을 자동 추가하지 않는다. 현재 상대 기록을 관리하는 쪽의 화면에만 `서로 관리하도록 전환`을 제공하고, 본인이 `owner`인 공간 선택과 상대에게 보호자 권한을 주는 별도 동의 전에는 전환 버튼을 비활성화한다.
- 어느 참여자에게나 `가족 관계 종료`를 제공한다. 확인 대화상자는 양방향이면 두 방향 보호자 접근을 함께 제거하고 단방향이면 현재 한 방향만 제거하며, 저장된 기록은 삭제하지 않고 재연결에는 새 요청과 동의가 필요하다고 설명한다.
- 활성 가족 관계에 연결된 구성원은 일반 `접근 제거` 동작을 제공하지 않고 관계 종료를 사용한다. 관계와 무관한 구성원 제거는 소유자에게만 계속 제공한다.
- 가족 관계 수락·전환·종료는 공간이나 건강 기록을 병합·변경·삭제하지 않으며, 상대 공간은 기록 대상을 전환해 관리한다고 설명한다.
- 수락·거절·취소 중에는 중복 실행을 막고 결과를 라이브 영역으로 전달한다.
- 가족 구성원 이름이나 역할만으로 의료 관계 또는 법적 보호자 자격을 추론하지 않는다.

## 11. 접근성 완료 조건

- 320px 폭과 200% 글자 확대에서 가로 스크롤 없이 핵심 동작 가능
- 키보드 포커스가 시각적으로 명확함
- 대화상자 포커스 이동·복귀와 Escape 닫기 지원
- 버튼, 날짜 이동, 선택 상태에 접근 가능한 이름 제공
- 입력 오류를 필드와 `aria-describedby`로 연결
- 로딩·완료·오류를 적절한 라이브 영역으로 전달
- 색상과 아이콘 없이도 기록 상태 이해 가능
- 모션 감소 설정 존중
