# 모바일 웹과 온라인 전용 정책

## 1. 목표

휴대폰에서 URL을 열거나 홈 화면 바로가기로 실행해 빠르게 기록한다. 설치형 외형은 편의를 위한 것이며 오프라인 앱을 의미하지 않는다.

## 2. 플랫폼

- Next.js
- React
- TypeScript
- Supabase
- Vercel
- 모바일 세로 화면 우선

최소 확인 환경:

- Android Chrome
- iPhone Safari
- 데스크톱 Chromium 기반 Playwright

## 3. 홈 화면 실행

manifest, 아이콘, 모바일 viewport, theme color, standalone 표시를 유지할 수 있다. 홈 화면 아이콘이나 브라우저 바로가기로 실행하면 첫 화면을 연다.

로그인, 접근 코드, 기기 승인 단계는 없다.

## 4. 온라인 전용

모든 조회와 저장은 Supabase 연결이 필요하다.

- 온라인이 아니거나 Supabase 요청이 실패하면 오류를 표시한다.
- 저장 실패를 완료로 표시하지 않는다.
- 네트워크가 돌아오면 사용자가 다시 시도하거나 화면이 최신 데이터를 다시 조회한다.
- 실패한 쓰기 요청을 나중에 자동 전송하지 않는다.
- 이전에 조회한 데이터를 영구 캐시해 오프라인 화면으로 제공하지 않는다.

`navigator.onLine`은 보조 신호일 뿐 저장 성공 근거가 아니다. 실제 Supabase 요청 결과를 기준으로 성공·실패를 판단한다.

## 5. 사용하지 않는 웹 저장 기능

다음은 사용하지 않는다.

- localStorage
- IndexedDB
- 앱 데이터용 쿠키
- Cache Storage의 앱/API 데이터 캐시
- 오프라인 작업 큐
- 백그라운드 동기화
- 브라우저와 서버 간 충돌 병합

서비스 워커가 기존 버전에 등록되어 있다면 제거하고 캐시된 앱 데이터가 남지 않도록 정리한다. 새 버전은 오프라인 동작을 위해 서비스 워커를 등록하지 않는다.

## 6. 연결 상태 UI

- 연결이 끊긴 것이 확인되면 “인터넷 연결이 필요합니다.”를 표시한다.
- 저장 버튼은 요청 불가능한 상태임을 텍스트와 비활성 상태로 전달한다.
- 조회 실패와 정상적인 빈 기록을 구분한다.
- 자동 저장·자동 동기화 약속을 표시하지 않는다.
- 다시 연결된 뒤 재조회 중 상태를 표시한다.

## 7. 다기기 최신성

모든 기기는 Supabase에서 같은 데이터를 읽는다.

- 쓰기 성공 후 현재 화면의 관련 데이터를 다시 조회한다.
- 화면 진입, 날짜 변경, 앱 포커스 복귀 시 필요하면 최신 데이터를 조회한다.
- 실시간 구독은 필수 요구사항이 아니다.
- 다른 기기의 변경을 로컬 데이터와 병합하지 않는다.

## 8. 터치와 화면

- 세로 화면과 최대 폭 28rem을 기본으로 한다.
- 주요 터치 영역은 64~72px, 최소 터치 영역은 48px다.
- 작은 아이콘이나 작은 텍스트만을 주요 동작으로 쓰지 않는다.
- safe area와 소프트 키보드를 고려한다.
- 가로 화면 전용 레이아웃은 제공하지 않지만 핵심 동작이 막히면 안 된다.

## 9. 제외 기능

- 오프라인 첫 화면과 최근 데이터
- 오프라인 투약·상태 기록
- 자동 동기화와 충돌 해결
- 백업·복원
- 푸시 알림과 리마인더
- 기기별 설정과 승인
