# 모바일 PWA, Web Push와 온라인 전용 정책

## 1. 목표

휴대폰에서 URL을 열거나 홈 화면 바로가기로 실행해 빠르게 기록하고, 사용자가 허용한 기기에는 투약 일정 Web Push를 보낸다. 설치형 외형과 푸시 서비스 워커는 편의를 위한 것이며 오프라인 앱을 의미하지 않는다.

## 2. 플랫폼

- Next.js
- React
- TypeScript
- Supabase
- Vercel
- 모바일 세로 화면 우선

최소 확인 환경:

- Android Chrome
- iOS/iPadOS 16.4 이상 Safari와 홈 화면에 추가한 앱
- 데스크톱 Chromium 기반 Playwright

## 3. 홈 화면 실행

manifest, 아이콘, 모바일 viewport, theme color, standalone 표시를 제공한다. 홈 화면 아이콘이나 브라우저 바로가기로 실행하면 첫 화면을 연다.

로그인, 접근 코드, 기기 승인 단계는 없다.

iPhone/iPad에서 알림을 사용하려면 Safari 공유 메뉴에서 `홈 화면에 추가`한 뒤 그 아이콘으로 앱을 열어야 한다. 홈 화면 추가는 알림 사용을 위한 플랫폼 절차이며 앱의 승인 기기 등록이 아니다.

## 4. 온라인 전용

모든 조회와 저장은 Supabase 연결이 필요하다.

- 온라인이 아니거나 Supabase 요청이 실패하면 오류를 표시한다.
- 저장 실패를 완료로 표시하지 않는다.
- 네트워크가 돌아오면 사용자가 다시 시도하거나 화면이 최신 데이터를 다시 조회한다.
- 실패한 쓰기 요청을 나중에 자동 전송하지 않는다.
- 이전에 조회한 데이터를 영구 캐시해 오프라인 화면으로 제공하지 않는다.

`navigator.onLine`은 보조 신호일 뿐 저장 성공 근거가 아니다. 실제 Supabase 요청 결과를 기준으로 성공·실패를 판단한다.

## 5. 사용하지 않는 웹 저장 기능

다음은 사용하지 않는다.

- localStorage
- IndexedDB
- 앱 데이터용 쿠키
- Cache Storage의 앱/API 데이터 캐시
- 오프라인 작업 큐
- 백그라운드 동기화
- 브라우저와 서버 간 충돌 병합

푸시 알림을 위해 `/sw.js` 서비스 워커를 등록한다. 이 서비스 워커의 알림 동작은 `push`와 `notificationclick`에서만 수행하고 `fetch` 핸들러나 앱/API 캐시를 두지 않는다. 설치·활성화할 때 이전 `medicine-app-*` 캐시가 있으면 정리한다.

브라우저가 관리하는 서비스 워커, 알림 권한과 Push 구독은 앱 데이터 로컬 저장이 아니다. 투약·상태·설정 데이터의 유일한 영구 저장소는 계속 Supabase다.

## 6. 투약 일정 Web Push — P1 완료

### 6.1 기기 설정

- 설정 화면에서 사용자가 `이 기기에서 알림 받기`를 눌렀을 때만 권한을 요청한다.
- 구독 후 `테스트 알림`으로 현재 기기의 수신 경로를 확인할 수 있다.
- `알림 끄기`는 Supabase 구독을 비활성화하고 브라우저 구독을 해제한다.
- 권한과 구독은 브라우저가 기기별로 관리하며 로그인, 접근 코드, 기기 승인을 대체하지 않는다.

### 6.2 일정 발송 흐름

1. Supabase Cron이 매분 Vault에 보관한 URL과 비밀값으로 Vercel 발송 API를 호출한다.
2. 서버는 활성 약의 활성 일정 중 최근 3분 범위에 도래한 한국 시각 일정을 확인한다.
3. 같은 한국 날짜와 일정의 삭제되지 않은 투약 기록이 이미 있으면 `skipped` 처리하고 보내지 않는다.
4. 기기·일정·예정 시각 unique 제약으로 같은 알림의 중복 생성을 막는다.
5. Vercel API가 VAPID로 Web Push를 전송하고 접수·실패 결과를 Supabase에 기록한다.
6. 사용자가 알림을 누르면 해당 약과 일정이 선택된 투약 기록 화면을 연다.

요청 중단이나 일시 실패는 예정 시각부터 5분 이내에 최대 3회까지 같은 delivery를 다시 시도한다. 시도 번호를 확인해 늦게 도착한 이전 요청이 새 결과를 덮어쓰지 않게 한다.

알림은 예정 시각과 약 이름, 기록 확인 안내만 표시한다. 복용을 지시하거나 미복용·지연을 판정하지 않는다.

### 6.3 전달 한계

push service가 발송 요청을 접수해도 기기에 정시에 표시되는 것은 보장되지 않는다. 네트워크, 브라우저, 운영체제의 집중 모드·절전 설정에 따라 늦게 도착하거나 도착하지 않을 수 있다. 설정 화면에 이 한계를 항상 표시하고 알림 수신 여부를 복용 기록으로 사용하지 않는다.

## 7. 연결 상태 UI

- 연결이 끊긴 것이 확인되면 “인터넷 연결이 필요합니다.”를 표시한다.
- 저장 버튼은 요청 불가능한 상태임을 텍스트와 비활성 상태로 전달한다.
- 조회 실패와 정상적인 빈 기록을 구분한다.
- 자동 저장·자동 동기화 약속을 표시하지 않는다.
- 다시 연결된 뒤 재조회 중 상태를 표시한다.

## 8. 다기기 최신성

모든 기기는 Supabase에서 같은 데이터를 읽는다.

- 쓰기 성공 후 현재 화면의 관련 데이터를 다시 조회한다.
- 화면 진입, 날짜 변경, 앱 포커스 복귀 시 필요하면 최신 데이터를 조회한다.
- 실시간 구독은 필수 요구사항이 아니다.
- 다른 기기의 변경을 로컬 데이터와 병합하지 않는다.

## 9. 터치와 화면

- 세로 화면과 최대 폭 28rem을 기본으로 한다.
- 주요 터치 영역은 64~72px, 최소 터치 영역은 48px다.
- 작은 아이콘이나 작은 텍스트만을 주요 동작으로 쓰지 않는다.
- safe area와 소프트 키보드를 고려한다.
- 가로 화면 전용 레이아웃은 제공하지 않지만 핵심 동작이 막히면 안 된다.

## 10. 제외 기능

- 오프라인 첫 화면과 최근 데이터
- 오프라인 투약·상태 기록
- 자동 동기화와 충돌 해결
- 백업·복원
- 앱 자체의 승인 기기 목록·차단 관리
- 알림의 정시·필수 도착 보장과 미복용·지연 판정
