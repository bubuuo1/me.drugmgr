# 투약 관리 도메인 설계

## 1. 핵심 개념

투약 관리는 세 종류의 데이터를 분리한다.

1. **약 설정**: 이름, 단위, 활성 상태
2. **복용 일정**: 예정 현지 시각, 기본 수량, 활성 상태
3. **실제 투약 로그**: 실제 복용 시각과 수량, 당시 설정의 스냅샷

설정은 앞으로 만들 기록에 적용되고, 과거 투약 로그는 당시 의미를 유지한다.

## 2. 약 설정

reset 스키마는 메스티논, 소론도, 셉트린정을 초기 값으로 넣지만 화면과 저장 로직은 Supabase의 활성 약 목록을 기준으로 한다.

약 필수 속성:

- 식별자
- 이름
- 단위
- 활성 상태
- 수량 선택지
- 생성·수정 시각

P1에서 이름과 단위를 바꿀 수 있다. 사용 이력이 있는 약은 물리 삭제하지 않고 비활성화한다.

## 3. 복용 일정

일정은 다음을 가진다.

- 약
- 예정 현지 시각
- 기본 수량
- 활성 상태

예정 시각은 `Asia/Seoul`의 `HH:mm` 의미로 저장한다. 날짜별 예정 순간이 필요할 때 현지 날짜와 결합한다.

일정 설정은 수정할 수 있지만 기존 투약 로그의 `schedule_time` 스냅샷은 바꾸지 않는다. 따라서 현재 일정과 과거 로그의 당시 예정 시각을 구분할 수 있다.

## 4. 실제 투약 로그

필수 값:

- `medication_id`
- 실제 복용 순간 `taken_at`
- 수량 `quantity`
- 중복 방지 키 `request_id`
- 당시 약 이름과 단위 스냅샷

선택 값:

- `schedule_id`
- 당시 예정 현지 날짜·시각 스냅샷
- 메모

`schedule_id`가 있으면 일정에서 시작한 기록이고, 없으면 일정과 연결되지 않은 추가 복용이다. 추가 복용 여부는 기록 분류일 뿐 의료적 적절성 판단이 아니다.

## 5. 예정 시간과 실제 시간

예정과 실제는 다른 값이다.

```text
예정: 2026-08-17 12:00 Asia/Seoul
실제: 2026-08-17T03:11:00Z  (= 12:11 KST)
```

- 일정 상태는 연결된 삭제되지 않은 로그가 있는지로 계산한다.
- 로그가 없으면 `아직 기록 없음`이다.
- 앱은 지각, 누락, 미복용을 자동 판정하지 않는다.
- 하나의 로그를 임의로 여러 일정에 연결하지 않는다.

## 6. 중복 방지

한 번의 사용자 제출은 하나의 `request_id`를 만든다.

- 저장 버튼 연타 중에는 같은 요청을 다시 보내지 않는다.
- 응답을 확실히 받지 못해 재시도할 때 같은 `request_id`를 사용한다.
- DB는 `request_id`에 unique 제약을 둔다.
- 동일 시각·수량의 별도 실제 복용은 서로 다른 `request_id`를 가지므로 기록할 수 있다.

단순히 약·수량·분 단위 시각이 같다는 이유로 중복을 자동 삭제하지 않는다.

## 7. 복용 수량

수량은 0보다 커야 한다. 단위는 약 설정에서 가져오되 로그에 당시 단위를 보존한다.

P0 수량 버튼은 약의 `quantity_options`와 직접 입력을 사용한다. 빈 선택지인 약은 한 번의 복용 여부를 수량 `1`로 기록하고 화면에는 횟수로 표시한다. 허용 형식과 상한은 입력 검증 규칙으로 명시하며 잘못된 값은 DB 요청 전에 차단한다.

## 8. 수정과 삭제 — P1

- 수량, 실제 복용 시각, 메모를 수정할 수 있다.
- 약 스냅샷과 당시 예정 스냅샷은 일반 기록 편집으로 바꾸지 않는다.
- 삭제는 `deleted_at`을 기록하는 soft delete다.
- 실행 취소는 `deleted_at`을 다시 비우는 명시적 복구다.
- 일반 합계, 마지막 복용, 일정 상태는 삭제되지 않은 로그만 사용한다.

## 9. 다기기 동작

모든 기기는 Supabase의 같은 행을 읽고 쓴다. 브라우저 로컬 사본을 병합하지 않는다.

- 쓰기 성공 후 관련 쿼리를 다시 조회한다.
- 화면 재진입 또는 포커스 복귀 시 최신 데이터를 다시 조회할 수 있다.
- 동시에 수정된 경우 마지막 DB 성공 결과를 기준으로 다시 표시한다.
- 정교한 공동 편집, 잠금, 역할별 충돌 해결은 범위가 아니다.

## 10. 의료 안전 경계

- 기본 수량은 입력 편의를 위한 설정이지 처방 지시가 아니다.
- 일정은 사용자가 설정한 계획이며 앱이 생성하거나 변경하지 않는다.
- 추가 복용을 기록할 수 있다는 사실이 추가 복용 권고를 뜻하지 않는다.
- 기록이 없더라도 앱은 지금 복용하라고 안내하지 않는다.
